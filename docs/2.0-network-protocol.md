# HoverNet 2.0 network protocol baseline

This document records the existing active protocol before 2.0 hardening. It is
descriptive, not an endorsement of host-native fields as the future format.

## Active architecture

Clients connect to RaceServer over TCP (default port `9600`). RaceServer owns
the lobby and race membership and relays gameplay messages between race peers.
Each client still simulates gameplay locally. The UDP socket, legacy direct
peer-to-peer paths, and `GameSimulation` are not the active hosted-race path.

## Existing frame

The packed frame prefix is three bytes:

| Offset | Size | Meaning |
| --- | ---: | --- |
| 0 | 2 | Datagram number (8 bits), queue (2 bits), message type (6 bits) |
| 2 | 1 | Payload length, `0..255` |
| 3 | N | Payload |

TCP is a byte stream: receivers must buffer partial frames and may receive
multiple frames in one read. A message type is limited to `0..63`.

Race IDs and client IDs are explicitly encoded as signed, four-byte
little-endian values. Automatic-element DLL, class, and room fields are signed,
two-byte little-endian values. Main-character state remains its deployed
20-byte bit-packed representation, now read and written bytewise without
unaligned host-word access. These changes preserve deployed wire bytes.

Missile, mine, and power-up state bodies still use native-layout structures;
they are the remaining cross-endian simulation payloads.

## Active message groups

- Lobby: set player name, list lobby users, lobby presence/leave, chat, list
  games, game rows, and list terminators.
- Race lifecycle: host with settings, join by race ID, joined/rejected reply,
  peer identity, ready, host start request, and race-start broadcast.
- Relayed gameplay: main-element state, auto-element creation, hit messages,
  chat, lag/keep-alive, and the existing session messages in `NetInterface`.
- Legacy: name-based create/join and direct peer/UDP setup messages remain in
  the implementation and require an explicit compatibility decision.

The canonical numeric definitions currently live in
`NetTarget/LinuxClient/RaceServerClient.h` and `NetTarget/Game2/NetInterface.cpp`.

## Current validation already present

- Message type is constrained to six bits when the server constructs frames.
- TCP receive queues retain partial and coalesced messages.
- Host requests validate the bundled track name and reject duplicate race names.
- Join-by-ID avoids ambiguous display names.
- Idle clients are swept and disconnected after the connection timeout.
- Smoke tests cover lobby presence, duplicate player names, chat bursts, host
  and join, start authorization, relay behavior, and invalid host settings.

## Implemented 2.0 negotiation

Before any lobby command, a 2.0 client sends a hello containing:

- fixed magic bytes;
- protocol major and minor versions encoded in network byte order;
- client capability flags;
- maximum frame size supported by the client.

The server responds with accepted version/capabilities or a bounded rejection
containing a machine-readable reason and short UTF-8 message. No gameplay or
lobby payload is processed until negotiation succeeds. The current server
accepts protocol major 2 and negotiates down to its supported minor version.
Other majors, malformed hellos, and pre-negotiation commands are rejected and
the connection is closed. The shared definition is in
`NetTarget/RaceServer/NetworkInterface/Protocol.h`.

During the rolling migration, legacy fallback is enabled by default and every
legacy connection is logged. Start RaceServer with `--require-protocol-2` to
disable fallback and reject pre-negotiation commands. This switch is temporary
and should become the default after supported clients have upgraded.

## Remaining hardening acceptance criteria

- Replace missile, mine, and power-up native-layout states with fixed byte formats.
- Reject incomplete frames after a timeout and payloads above the negotiated
  limit without over-reading or desynchronizing the following frame.
- Bound and validate UTF-8 player, race, track, and chat strings.
- Validate message direction and connection state before dispatch.
- Rate-limit connections, chat, race creation, and invalid messages.
- Fuzz the decoder and test fragmented/coalesced frames and all rejection paths.
- Log rejection reason and connection identity without logging untrusted text as
  a format string or exposing private state.
