# Signing catalogues and release files

`HoverNetSign` signs and verifies files with Ed25519 (RFC 8032), so a catalogue or a release can be shown to come from the project and not
from whoever happens to host a mirror.

    HoverNetSign keygen release.key            # creates the secret key (owner-only) and prints the public key
    HoverNetSign sign release.key SHA256SUMS   # writes SHA256SUMS.sig (128 hex characters)
    HoverNetSign verify PUBLICKEY SHA256SUMS   # exit 0 when SHA256SUMS.sig is a valid signature by that key

## What is signed

The signature covers the file's exact bytes. For a release, sign `SHA256SUMS` (which names every package by hash); for the community
catalogue, sign `CommunityTracks.tsv` (which names every track by SHA-256). Verifying the signature and then the hashes covers every file.

## Keys

- Generate the release key on a machine that is not a build server, back it up offline, and never put it in the repository or in CI. The
  public key (64 hex characters) is published in the repository and on the download page, and is compiled into clients once clients
  verify catalogues.
- To rotate a key, sign the new public key with the old one and publish both signatures for one release before retiring the old key.
  If the key is lost or leaked, publish a new key out of band; clients that pin the old key need an update, which is why the key is
  compiled in and not downloaded.

## Implementation and checking

`NetTarget/Authority/Ed25519.*` is written from RFC 8032 and checked three ways: the RFC test vectors (`HoverNetEd25519`), an independent
reference implementation in Python that must produce identical public keys and signatures, and cross-verification both ways on random
messages (`HoverNetSigning`). It is not constant-time audited code; it only ever handles files the owner chooses to sign, never network
input from strangers except the public-key side of verification, which has no secrets.

## Not done yet

The downloader does not check signatures (there is no production key yet to compile in), `scripts/make-release-checksums.sh` signs `SHA256SUMS` when `HOVERNET_SIGN_TOOL` and `HOVERNET_SIGN_KEY` are set (tried by hand on a throwaway key) but the release jobs do not set them, and
no independent review has been done. Until a key is generated by the project owner, nothing is signed and nothing may be described as signed.
